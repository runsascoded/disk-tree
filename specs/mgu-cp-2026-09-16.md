## Proposed roadmap (spec-driven, prioritized by reuse × readiness)

1. **Comms** (`discord_api` + digest → a generic `disk_tree` notify/digest module).
   Highest reuse, least entanglement with the mark axis; net-new to dt. Slack
   sibling to be added.
2. **IaC recipes**: reconcile mgu's container `job/` + `cloudbuild.yaml` with dt's
   `capture`/`reduce` + `reduce.yml` + `specs/iac.md` into shared, documented
   recipes (container **and** GHA).
3. **Mark & sweep** (`dt_cloud` sweep/mark/rules/reactive) → a reusable engine.
   **Blocked on gcs↔cw-s3 convergence of the mark axis** — upstream the unified
   design, not one deployment's.
4. **Serverless BE** (`site/functions/_lib`) ↔ dt's `ui/cfn`: reconcile the
   overlapping read/planning layer; the mark/owner/scope API is net-new.
